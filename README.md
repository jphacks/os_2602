## 製品概要

### 背景（製品開発のきっかけ、課題等）

**「あなたは、今いる場所の音をどれくらい知っていますか？」**

私たちの身の回りには、自動車の走行音、電車の通過音、工事現場の騒音、人々の話し声、鳥のさえずりなど、さまざまな音が存在しています。

しかし、音には大きな特徴があります。それは、**「目に見えない」ということです。**

例えば、引っ越し先を探しているとき、その地域が夜間にどれくらい静かなのかを事前に把握することは容易ではありません。また、勉強や在宅ワークに集中できる場所を探す際にも、実際に足を運ばなければ周囲の音環境がわからないことがあります。

さらに、音の大きさを示すデシベル（dB）の数値だけでは、その音が何によって発生しているのかを判断できません。同じ70dBであっても、電車の走行音とセミの鳴き声では、人が受ける印象は大きく異なります。

つまり、街の音環境を理解するためには、単に音の大きさを測るだけでなく、**「どこで」「いつ」「どのような音が」「どれくらい鳴っているのか」**を知ることが重要です。

一方、街のさまざまな場所で音を継続的に測定し、その情報を収集するには、多くの人の協力が必要になります。しかし、音を測定すること自体に楽しさや目的がなければ、ユーザーが自発的にデータ収集を続けることは難しいと考えました。

そこで私たちは、次のように考えました。

**「音を測ること自体をゲームにすれば、楽しみながら街の音環境を可視化できるのではないか？」**

この発想から生まれたのが、位置情報ゲーム型Webアプリケーション **「dether」** です。

---

### 製品説明（具体的な製品の説明）

**detherは、スマートフォンを使って街の音を測定し、バッジを収集しながら音環境を可視化する位置情報ゲーム型Webアプリケーションです。**

ユーザーは散歩中に気になる場所を見つけたら、「調査する」ボタンを押すことで、その場の音を測定できます。

測定された音量と位置情報は記録され、一定の条件を満たすとバッジを獲得できます。また、測定した音には「電車」「車」「工事」「セミ」などのタグを付けることができ、その場所でどのような音が発生しているのかを記録できます。

これらの測定情報を地図上に反映することで、街の音環境を視覚的に把握できる仕組みを目指しています。

専用の測定機器は必要ありません。スマートフォンのマイクと位置情報を利用し、普段の散歩を街の音を探す冒険へと変えます。

#### 基本的な利用の流れ

**STEP 1：街の音を調査する**

スマートフォンでdetherを起動し、「調査する」ボタンを押します。Web Audio APIを利用して周囲の音を測定し、音量をリアルタイムで表示します。

通常の測定時間は10秒間です。静寂系のバッジでは、条件に応じて30〜60秒間の測定を行います。

**STEP 2：バッジを獲得する**

測定した音量が一定の条件を満たすと、バッジを獲得できます。

大きな音だけでなく、静かな場所を発見した場合にもバッジを獲得できるため、さまざまな音環境を探索する楽しさがあります。

**STEP 3：音の種類をタグで記録する**

バッジ獲得後、その場所で聞こえた音の種類をタグで記録できます。

タグは複数選択でき、文章や写真による投稿機能も想定しています。タグを選ぶだけでも記録できるため、手軽に参加できます。

**STEP 4：地図で音環境を確認する**

測定された音量やタグ情報を地図上に反映します。

ユーザーは、自分が獲得したバッジや、ほかのユーザーが収集した音環境データを確認できます。

**STEP 5：街を探索し、新しい音を発見する**

さまざまな場所や時間帯で音を測定し、新しいバッジや季節限定のタグを収集します。

こうしたゲーム体験によって蓄積された記録が、街の音環境を可視化するためのデータになります。

**detherでは、一人ひとりのゲーム体験が、街の音環境を知るための情報につながります。**

### 特長

#### 1. 音を探してバッジを集める位置情報ゲーム

detherでは、音量の測定結果に応じてバッジを獲得できるゲームシステムを採用します。

一般的な騒音計アプリは音量を数値で確認することが主な目的ですが、detherでは測定すること自体をゲームとして楽しめます。

バッジは「大きい音系」と「静寂系」の2系統に分かれています。

| バッジ名 | 獲得条件 | 音環境の目安 |
|---|---|---|
| 90dBバッジ | 10秒間の平均音量が90dB以上 | 大型車両が通行する幹線道路沿い、工事現場周辺 |
| 80dBバッジ | 10秒間の平均音量が80dB以上 | 交通量の多い道路沿い、踏切周辺 |
| 70dBバッジ | 10秒間の平均音量が70dB以上 | にぎやかな商店街、セミの鳴く公園 |
| 静寂バッジ | 40dB以下を30秒間維持 | 人通りの少ない住宅街、静かな公園 |
| 深い静寂バッジ | 35dB以下を60秒間維持 | 深夜の閑静な住宅街、自然豊かな散歩道 |

※ 上記の音環境はあくまで目安であり、実際の測定値は場所や時間帯、周囲の状況、端末によって異なります。バッジの獲得条件は実機検証によって調整する場合があります。

detherでは、建物内や乗り物内での測定ではなく、散歩中に訪れる住宅街・公園・商店街・道路沿いなど、**屋外の音環境を主な測定対象**としています。

さらに、昼と夜では別のバッジとして扱います。

- 昼：6時〜22時
- 夜：22時〜翌6時

これにより、5種類のバッジを昼夜それぞれで収集でき、**合計10種類のバッジ**を楽しめます。

例えば、昼間はにぎやかな商店街でも、夜間には静かな環境に変化する場合があります。同じ場所でも時間帯によって異なる発見ができることが、detherの魅力です。

また、同じ場所で繰り返しバッジを獲得した場合でも、地図が見づらくならないように「50mルール」を導入します。

半径50m以内に存在する同じ系統・同じ時間帯のバッジについては、強いバッジを優先して表示します。

ただし、表示されなくなったバッジの測定記録も保持し、ヒートマップの集計に利用します。

---

#### 2. 音の大きさと種類を可視化する騒音ヒートマップ

detherでは、ユーザーが測定した音量を地図上に反映する「騒音ヒートマップ」を実装する計画です。

一般的なヒートマップでは、データの密集度によって色分けされる場合があります。しかし、この方法では、静かな場所でも測定回数が多ければ騒がしい場所のように見えてしまう可能性があります。

そこでdetherでは、地図を50〜100m程度のマス目に分割し、それぞれのマスに含まれる測定記録の平均dBを計算します。

その平均値に応じて色を変化させることで、測定回数ではなく、記録された音量を基に街の騒がしさを表現します。

さらに、各マスで最も多く選択された音のタグを「代表タグ」として表示します。

例えば、以下のような情報を地図上で確認できるようにします。

- 電車の通過音が多く記録された地域
- 工事の音が多く記録された地域
- セミの鳴き声が多く記録された地域
- 静かな環境が多く記録された地域

これによって、単に騒がしい場所を調べるだけでなく、**「どのような音によって騒がしいのか」まで把握できる地図**を目指します。

また、時間帯を切り替えることで、昼と夜の音環境を比較できます。

##### 3種類のマップ

detherでは、用途に合わせて3種類のマップを用意する計画です。

| マップ | 主な機能 |
|---|---|
| ローカルマップ | 自分が獲得したバッジを表示する |
| 全国マップ | ほかのユーザーが獲得したバッジや投稿を確認する |
| ヒートマップ | エリアごとの平均音量と代表タグを可視化する |

これにより、個人のゲーム体験と、ユーザー全体で収集した音環境データを結び付けます。

---

#### 3. 季節限定の音を集める「季節タグ」

detherでは、バッジとは別の収集要素として「季節タグ」を導入します。

季節タグは、特定の期間だけ選択できるタグです。

| 季節タグ | 出現期間 |
|---|---|
| 風鈴 | 6月〜8月 |
| 花火 | 7月〜8月 |
| 秋の虫の声 | 9月〜11月 |
| 祭りの太鼓 | 祭りの開催時期 |
| 除夜の鐘 | 12月31日の夜 |
| 初詣のにぎわい | 1月1日〜3日 |

※ 上記は企画段階の例であり、実際のタグや出現期間は変更する場合があります。

季節タグは、あらかじめ設定された期間に応じて自動的に表示されます。

例えば、夏には風鈴や花火、秋には虫の鳴き声など、その季節ならではの音を収集できます。

また、収集した季節タグをマイページの「季節タグ図鑑」で確認できる機能も検討しています。

これにより、音量の大小だけでなく、**季節の変化や街の文化を音から楽しむ体験**を提供します。

「今しか聞けない音」を探す楽しさによって、継続して街を探索するきっかけを生み出します。

### 解決出来ること

detherは、音を測定するゲームを通して、以下のような課題の解決を目指しています。

**1. 街の音環境を事前に知ることができる**

引っ越し先や通勤・通学先など、実際に生活を始めるまで把握しにくい音環境を、地図上の情報から確認できるようにします。

特に、昼と夜の違いを比較できることは、生活環境を判断する際の参考情報になります。

**2. 静かな場所を探しやすくなる**

勉強や読書、在宅ワークなどに適した静かな場所を探すための情報を提供します。

また、「静寂バッジ」を設けることで、静かな場所を発見すること自体にも楽しさを持たせています。

**3. 騒音の発生源を把握できる**

単なる音量の数値だけではわからない、音の発生源に関する情報をタグによって記録できます。

これにより、同じ音量でも、その地域でどのような音が発生しているのかを知ることができます。

**4. ユーザー参加型の音環境データを収集できる**

ユーザーがゲームを楽しむ過程で、測定データが自然に蓄積されます。

その結果、多くのユーザーが参加するほど、さまざまな場所の音環境に関する情報が集まる仕組みを目指しています。

**5. 街の新しい魅力を発見できる**

音は騒音として問題になるだけでなく、その地域の文化や季節を感じる要素でもあります。

祭りの太鼓、風鈴、鳥のさえずり、虫の鳴き声などを記録することで、普段は意識しない街の魅力を再発見するきっかけになります。

**detherは、目に見えない街の音を可視化し、日常の散歩を新しい発見につながる体験へと変えます。**

**4. 音環境の時間的変化の可視化**

同じ場所の音環境が、季節や時間帯、工事の前後などでどのように変化したのかを比較できる機能を検討しています。

### 注力したこと（こだわり等）

- **ゲーム体験と社会的価値の両立**

  音の測定という行為をゲームにすることで、ユーザーが楽しみながら街の音環境データを収集できる仕組みにこだわりました。

  単なる娯楽で終わるのではなく、収集されたデータが誰かの生活に役立つ情報になることを目指しています。

- **音量と音の種類を組み合わせた可視化**

  音の大きさだけでは、その場所の音環境を十分に理解できません。

  そこで、測定した音量に加えてタグを記録し、地図上に代表タグを表示する仕組みを設計しました。

  これにより、数値だけではわからない音環境の特徴を可視化します。

- **スマートフォンで手軽に利用できる設計**

  専用の測定機器を必要とせず、スマートフォンのブラウザから利用できるWebアプリとして設計しました。

  また、PWAへの対応によって、ホーム画面からアプリのように起動できる体験を目指しています。

- **プライバシーと安全性への配慮**

  detherでは、マイクと位置情報を利用するため、利用者のプライバシーと安全性を重要視しています。

  音声そのものは保存せず、端末内で音量情報へ変換する仕組みを採用します。

  また、公開マップでは位置情報を一定範囲でぼかし、投稿写真に含まれるEXIF情報を削除する設計です。

  さらに、危険な場所への立ち入りや歩きスマホを防ぐための注意喚起も検討しています。

- **短期間での開発を実現するチーム体制**

  今回のハッカソンでは、限られた時間で開発を進める必要があります。

  そこで、フロントエンドとバックエンドを完全に分離するのではなく、機能単位で担当を分けるフルスタック開発方式を採用しました。

  各担当者が画面からAPIまでを一貫して実装することで、効率的な並行開発を目指しています。

## 開発技術

### 活用した技術

#### API・データ

- **Web Audio API**
  - スマートフォンのマイクから音声入力を取得
  - 音声データの解析
  - 推定dBの算出
  - 測定中の音量表示

- **Geolocation API**
  - ユーザーの現在位置を取得
  - 緯度・経度を測定記録と関連付け
  - バッジ獲得地点の記録

- **Google Maps JavaScript API**
  - ローカルマップの表示
  - 全国マップの表示
  - 騒音ヒートマップの描画
  - 測定地点やバッジの表示
  - 時間帯による表示内容の切り替え

- **音環境データ**
  - Measurement：測定日時、位置情報、平均音量、最大音量など
  - TimeBand：昼・夜などの時間帯情報
  - BadgeType：バッジの種類と獲得条件
  - UserBadge：ユーザーが獲得したバッジ
  - Tag：共通タグ・季節タグ
  - MeasurementTag：測定記録とタグの関連付け
  - Post：バッジに関連する投稿情報

※ 音声そのものは保存せず、数値化した測定結果や位置情報、タグを保存する設計です。

#### ハッカソンで開発した独自機能・技術

以下は、Hack Dayで開発することを計画している主な独自機能です。

実装完了後、実際のソースコードへのリンクやコミットIDを追記します。

**1. Web Audio APIを活用した音量推定システム**

Web Audio APIで取得した音声データを解析し、周囲の音量を推定する機能です。

ブラウザから取得できる相対的な音量データ（dBFS）を基に補正値を加え、推定dBを算出する方式を採用します。

また、瞬間的な最大値ではなく、測定時間中の平均値を基にバッジの獲得条件を判定します。

主な技術的工夫は以下のとおりです。

- 音声入力のリアルタイム解析
- dBFSを基にした推定dBの算出
- 一定時間の平均値による判定
- 端末ごとの測定値の違いを考慮した補正
- 音声データをサーバーに保存しない設計

**2. 音量と継続時間に基づくバッジ判定システム**

測定した音量と継続時間を基に、バッジの獲得条件を判定する機能です。

大きな音のバッジでは10秒間の平均音量を利用し、静寂系のバッジでは一定以下の音量が継続した時間を判定条件としています。

また、昼と夜の時間帯を区別することで、同じバッジでも異なる収集対象として管理します。
